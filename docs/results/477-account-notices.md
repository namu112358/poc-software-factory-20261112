# [SF-D][Epic] 身に覚えのないログインやロックに、本人が気づけるようにする（#477）の結果

連続運転 D（2026-11-13、計画は #122）のうち、身に覚えのないログインに気づいて自分のアカウントを守りたいメンバーの立場で使って見つけた困りごとを直した Epic の結果です。使う人の立場で動かす回の 7 回目です（1〜6 回目は #411・#421・#426・#435・#444・#465。台帳 E16）。

## 確かめたいこと

- 「良くしたいこと」の 5（身に覚えのないログインに気づける）で見つけた困りごと（`docs/product.md`、PR #480）から作った Issue が、受入条件どおりに直るか。
- 認証に関わる難しい変更が、人が差分を読んだうえで、受入条件どおりに入るか。

## 見つけ方

2026-11-13 01:49 に、main（cead953）を `npm start` で起動した。Playwright で、userAgent を変えたブラウザのコンテキストを端末に見立て、次の場面を試した。

- 佐藤の PC がログイン中に、見慣れない端末から佐藤の ID で 3 回誤ってからログインに成功する（パスワードが漏れた想定）。
- ほかの人が鈴木の ID で 5 回誤り、鈴木をロックする。
- ログイン中の端末の一覧から端末を切る。パスワードを変える。すべての端末からログアウトする。

操作と記録はサブエージェント（sonnet）に任せ、困りごとの見立ては D がした。

困りごとが 2 つ見つかった。

- 攻撃者の端末のログインは、本人の端末に何も知らされなかった。
  - それまでのパスワードの誤りの知らせは、ログインに成功した攻撃者の画面に出て、本人には出なかった。
- ロックされた本人の画面には「しばらくして」とだけ出て、あと何分かは出なかった。
  - ロックが明けたあとも、ロックされたことは知らされなかった。

次のことは、困りごとにしなかった。

- ログイン中の端末の一覧で、見慣れない端末を見分けて切れる。
- パスワードを変えると、ほかの端末のログインが切れる。
- すべての端末からログアウトできる。

ロックの方針（5 回の誤りで 15 分。ID を知っていれば、誰でも本人を締め出せる）は、認証の設定に当たるので変えず、人の判断に残した。

確かめ直しの中身:

1. #478（新しいログインの知らせ）
   - 端末 B（`python-requests/2.31`）が佐藤の ID でログインすると、端末 A に「新しいログインがありました: 不明な端末、2026/11/13 11:42」が出た。
   - その前の 3 回の誤りも、端末 A に出た。
   - 「確かめた」か「ログイン中の端末」を開くと、知らせは消えた。
   - 鈴木のログインは、佐藤の知らせに出なかった。
   - `GET /api/me` に `loginNotice` が入った。
   - 知らせは `role="status"` で、「本文へ移動」とナビの並びは崩れていなかった。
2. #479（ロックの知らせ）
   - 5 回目の誤りで「ログインをロックしました。あと 15 分でログインできます。」と出た。ロック中も「あと 15 分」と出て、API の値と一致した。
   - 明けたあとのログインで「ログインが 1 回ロックされました（最後は 2026/11/13 11:42）」と出た。
   - ロックの方針（5 回・15 分・ロック中の試行で延びない）は変わっていなかった。
   - 存在しない ID でも、応答の状態と文言は同じだった（ID があるかを推し量れない）。

時刻はすべて UTC。ready・着手の時刻は GitHub のラベルのイベント、マージの時刻は PR のマージの時刻による。ロックが明けた場面は、15 分待たずに、DB のロックの期限を過去に書き換えて確かめた。

## 分かったこと

- 本人に知らせるべきことが、ログインに成功した側のセッションに写る作りだった。そのため、乗っ取られた場面でだけ、本人に届かなかった。1 人で使う場面の受入条件とテストでは見えず、端末を 2 つ用意して使って初めて見えた。
- 認証に関わる 2 件は、どちらも割り当ての役が難しい用と判定し、レビューが `risk:high` を付けた。D は差分を読み、ロックの方針が変わっていないことと、存在しない ID でも応答の形が同じことを確かめてから merge を付けた。
- 2 件は同じファイル（`src/lib/auth.ts`）を変えるので、#479 は #478 を待った。#478 のマージから 82 秒で、人の手なしに着手した。

## 残したこと

- ロックの方針（5 回で 15 分、ID ごと）は人の判断。今のままだと、ID を知っていれば誰でも本人を 15 分締め出せる。
- 「パスワードを誤ったログインが N 回」の N には、ロック中の試行（正しいパスワードを含む）も入る。今の作りのままで、変えていない。
- 見慣れない端末は「不明な端末」と出るだけで、場所や IP は出ない（対象外にした）。
