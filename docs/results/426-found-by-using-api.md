# [SF-D][Epic] 連携スクリプトの立場で使って見つかった困りごとを直す（#426）の結果

連続運転 D（2026-11-12、計画は #122）のうち、社内の連携スクリプトの立場で API だけを使って見つけた困りごとを直した Epic の結果です。使う人の立場で動かす回の 3 回目です。1 回目はメンバー（#411）、2 回目は取りまとめる人（#421）でした（台帳 E16）。

## 確かめたいこと

連携スクリプトの立場で API だけを使って見つけた困りごと（`docs/product.md`、#424）から作った Issue が、受入条件どおりに直るか。画面を使った 1 回目・2 回目と比べて、見つかる困りごとの種類が違うか。

## 見つけ方

2026-11-12 22:13 に、main（#423 のマージ後）を `npm start` で起動した。`curl` で `POST /api/login` からログインし、次の API を順に呼んだ。

- 一覧（絞り込みを変えて）
- 作成（正しい入力と誤った入力）
- 更新・削除・元に戻す
- まとめての変更・書き出し
- 候補の一覧
- ログアウト

どれも動き、誤った入力には `{ error, details }` で 400 が返った。そのうえで、困りごとが 1 つ見つかった。タスク一覧の API が、画面と同じ絞り込みを受け付けない。

- 複数の担当者を頼むと、最初の 1 人分だけを返す。
- 期限での絞り込みを、黙って無視する。

次の 2 つは、困りごとにしなかった。

- 更新の衝突: 本文に `expectedUpdatedAt` を渡せば 409 で断られる。スクリプトの側に手段がある。
- ログアウトがリダイレクト（303）を返すこと: 小さいので Issue にしなかった。

## 判定

| 確かめたいこと | 結果 | 判定 |
|---|---|---|
| 受入条件どおりに直る | マージした。22:31 に同じ API の呼び出しで確かめ直し、直ったことを確かめた（下の表） | 当たり |
| 画面を使った回と、見つかる困りごとの種類が違う | 1 回目（メンバー）は入口と使いにくさ、2 回目（取りまとめる人）は権限、3 回目（連携スクリプト）は画面と API の振る舞いのずれだった | 違った（3 回で 3 種類） |

時刻はすべて UTC。ready・着手・マージの時刻は、D の取りまとめ役が 60 秒ごとに取った GitHub の状態の記録と Issue が閉じた時刻による。

## 分かったこと

- 画面の機能を足すときに「API は対象外」とした Issue（#348・#392・#398）が重なり、画面と API の振る舞いが少しずつずれていった。1 つずつの Issue では対象外は正しい判断だった。ただ、API を使う人の立場で見ると、結果が黙って変わる困りごとになっていた。
- 直し方は、画面と CSV が使っている絞り込みの検証を、API でもそのまま使うことだった。API のための別の判定を作らなかったので、画面・CSV・API の結果がそろった。
- 使う人の立場で動かす回は、3 回とも違う種類の困りごとを見つけた。立場を変えることに意味がある。

## 残したこと

- 「API は対象外」とした Issue が、ほかにも画面と API のずれを残していないかは、確かめていない。
- 使う人の立場で動かす回を、何件マージするごとに、どの立場で入れるとよいかは、まだ決めていない（台帳 E16）。
