## 分かったこと

- 止まりも待ちも無ければ、小さな変更は ready から 8〜18 分でマージまで進んだ（7 件）。
- 時間を延ばしたのは、作業そのものではなく、止まりと待ちだった。
  - 止まり: 実装の役が CI を早く諦めた（#184）、利用上限（#219）、main の CI を壊した不具合（#362）。
  - 待ち: 同じファイルを変える Issue の待ち。人の役の遅れもあった。
- レビューの必須の指摘は 16 件で 2 件だった。どちらも、受入条件や対象外の範囲を外れていた点を、レビューの役が受入条件と照らして見つけた。
- 後半の Issue（#347 以降）は、docs/product.md の「良くしたいこと」から作った。前半の Issue より、受入条件に「ログインした時点で決まる」「対象外: API」のような境目が増えた。その境目が、レビューの指摘の対象になった。
- main の不具合（#362）は、この Epic の 2 件（#347・#348）を、変更の中身と関係なくキューから外した。

## 残したこと

- 人の役の遅れ（レビューの ok から `merge:requested` まで）は、`merge-check` の ok を知らせる監視を足してからは約 1 分になった。ただ、人の役のセッション自体が止まると、遅れは残る。
