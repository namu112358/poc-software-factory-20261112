# [SF-D][Epic] 休みと引き継ぎの立場で使って見つかった困りごとを直す（#435）の結果

連続運転 D（2026-11-12、計画は #122）のうち、休みと引き継ぎの立場でアプリを使って見つけた困りごとを直した Epic の結果です。使う人の立場で動かす回の 4 回目で、立場は次の 3 人です。

- 休みに入るメンバー（鈴木）
- 引き継ぐ取りまとめる人（田中）
- 引き継がれるメンバー（佐藤）

これまでの回は、メンバー（#411）、取りまとめる人（#421）、連携スクリプト（#426）でした（台帳 E16）。

## 確かめたいこと

- 休みと引き継ぎの立場で見つけた困りごと（`docs/product.md`、PR #441）から作った Issue が、受入条件どおりに直るか。
- これまでの 3 回と比べて、見つかる困りごとの種類が違うか。

## 見つけ方

2026-11-12 22:45 に、main（#432 のマージ後）を `npm start` で起動した。Playwright と `curl` で、次の流れを順に操作した。

1. 鈴木が 11/13〜11/20 の休みを登録する。
2. 田中が、メンバーの一覧で鈴木の休みと担当を見る。鈴木の 2 件を、まとめて佐藤へ替える。
3. 担当者の履歴を見る。
4. 佐藤が、新しく担当になったタスクの知らせを見る。
5. 佐藤が別の端末でもログインし、ログイン中の端末の一覧を見る。
6. 田中が新しいタスクを作り、担当者を選ぶ。

困りごとが 2 つ見つかった。

- 鈴木の担当をすべて替えたあとに鈴木で絞り込むと、全員のタスク 7 件が出た。
  - 画面・CSV・API のどれも同じだった。
  - 担当者の値を「今タスクを持っている人」と照らしていたため、担当が無くなった鈴木が「不正な値」とみなされ、「指定なし」になっていた。
- 新しいタスクを作る画面では、担当者の選択肢に、休み中であることとタスクの数が出なかった。担当の変更とまとめての変更の画面には出ていた。

次の 3 つは、使って確かめたうえで、困りごとにしなかった。

- 担当者の履歴に「田中 が 鈴木 → 佐藤 に変更」と残る。
- 新しく担当になったタスクは、次のログインのときに知らされる。
- ほかの端末のログインは「ログイン中の端末」に出て、その端末だけを切れる。

## 分かったこと

- 引き継ぎのように、ある状態が「無くなる」操作のあとに、困りごとが出た。担当者の絞り込みは、それまでの Issue で何度も足したり直したりしてきた（#348・#392・#425）。それでも、担当が 0 件の人という場合は、使ってみるまで見つからなかった。
- 同じ「担当者を選ぶ」でも、選択肢の作り方が画面ごとに違った。#375 で件数を足したときに、新しいタスクの画面が抜けていた。
  - 受入条件に「ほかの入口にも効くか」を書く決まり（台帳 E15、機能の Issue テンプレート）は、#375 の後にできた。
- レビューの役は、#437 で「これから始まる休み」の抜けを見つけた。
- D の誤りが 1 つあった。結果のまとめと `docs/product.md` の PR を、`claude/` で始まらないブランチで出した（#433・#434）。そのため、レビューの Routine が起動しなかった。
  - `claude/` のブランチで出し直した（#440・#441）。
  - 出し直した #441 には、レビューで必須の指摘が付いた。ブランチを #439 のマージ前の main から作っていたため、直った困りごとを「まだ解決していない」と書いていた。

## 残したこと

- 担当者を選ぶ選択肢の作り方が、画面ごとに分かれている（担当の変更・まとめての変更・新しいタスク・絞り込み）。今回は見せ方をそろえただけで、作り方を 1 つにまとめてはいない。
- 使う人の立場で動かす回を、何件マージするごとに、どの立場で入れるとよいかは、まだ決めていない（台帳 E16）。
