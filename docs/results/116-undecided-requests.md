## 分かったこと

- 決めていない点は、勝手に決められずに質問になった。どの質問にも選択肢があり、#378・#379 では、それぞれの長所と短所と、受入条件のどこが変わるかも書かれていた。
- 質問への答えは、レビューの必須の指摘を 0 件にした。この Epic の 9 件はすべて 1 回目のレビューで ok だった（#378 の 2 回目は、衝突の直しの後の確かめ）。
- 質問の往復そのものは短かった（答えるまで 0〜2 分）。時間を延ばしたのは、着手までの待ちと止まりだった。
- 人が先に答えておくと、質問の往復が要らなくなった（#92）。
- 質問する役は、#285 で実装の役から割り当ての役に移った。割り当ての役が質問すると、実装のセッションを起こさずに済む。ただ、割り当ての Routine が起動しないと、質問も来ない（#357）。

## 残したこと

- 実装の役が CI の失敗で止まるとき、`status:needs-human` を付けて判断を求める場合（#350）と、黙って止まる場合（#351）があった。同じ状況で振る舞いが分かれた理由は調べていない。
