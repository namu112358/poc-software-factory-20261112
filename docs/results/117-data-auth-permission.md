## 分かったこと

- 見分けは確実だった。レビューの役は 9 件とも `risk:high` を付けた。この Epic の外でも、データの見える範囲が変わる API（#89）に付けていて、付けすぎではなく、妥当な範囲だった。
- 人が差分を読む段は、マージを止めるほどの問題は見つけなかった。ただ、確かめる点（本人に絞っているか、マイグレーションが足すだけか、秘密を出さないか）を、人が毎回同じ観点で読めた。権限の穴は、この Epic の外の #333 で、実装の役が自分で見つけて質問した。
- 時間を延ばしたのは、作業そのものではなく、着手までの待ちだった（#183・#219・#250・#275）。着手してからは、どれも 1 回目のレビューで ok になった。
- 人の役の遅れも待ちになった。#349 は、レビューの ok（17:48）から、人が差分を読んで `merge:requested` を付ける（18:23）まで 35 分かかった。#334 は 5 分（17:31 → 17:36）だった。人の役の監視がラベルの変化しか見ておらず、ok に気づかなかったため。18:25 からは、`merge-check` が ok になったら知らせるようにした。

## 残したこと

- 人が差分を読む時間（ok から `merge:requested` まで）を、`risk:high` の PR とそれ以外で分けて集めていない。D の全体の集計で扱う。
