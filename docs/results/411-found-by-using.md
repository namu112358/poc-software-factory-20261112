# [SF-D][Epic] 使ってみて見つかった困りごとを直す（#411）の結果

連続運転 D（2026-11-12、計画は #122）のうち、アプリを実際に使う人の立場で動かして見つけた困りごとを直した Epic の結果です。

## 確かめたいこと

アプリを使う人の立場で動かして見つけた困りごと（`docs/product.md` の「使ってみて見つかった、まだ解決していないこと」、#407）から作った Issue が、受入条件どおりに直り、使う人の困りごとが減るか。机の上で考えた Issue と比べて、レビューの指摘や修正の往復が増えるか減るか。

## 見つけ方

2026-11-12 21:20 に、main（#404 のマージ後）を `npm start` で起動し、Playwright で佐藤としてログインした。一覧・詳細・編集・担当替え・タグ・コメントと、設定の画面を一通り使った。エラーは、存在しないタスクを開いたときの 404（意図どおり）だけだった。そのうえで、使う人が困る点が 3 つ見つかった。

- 延長の申請を、画面から出せない（API だけ）。承認する側の画面はそろっているのに、入口が無い。
- 画面の上の移動先が 11 個で、語の途中で折り返す。一覧の説明文が今の機能と合っていない。
- 担当者の複数選択が、Ctrl／Cmd を押しながら選ぶ前提になっている。

どれも、それまでに出した Issue の受入条件とレビューでは見つからなかった。1 つ目は、承認待ちの一覧・承認・却下・自分の申請の結果・待ちの強調（#312・#333・#367・#384）を順に作るあいだ、入口が無いことにだれも気づかなかった。

## 判定

| 確かめたいこと | 結果 | 判定 |
|---|---|---|
| 受入条件どおりに直る | 3 件ともマージした。21:45 に同じ流れで使い直し、3 つとも直ったことを確かめた（下の表） | 当たり |
| 使う人の困りごとが減る | 延長の申請の入口ができた。移動先が 9 個で 1 行に収まった。複数選択がチェックボックスになった | 当たり |
| 机の上の Issue と比べて、指摘や修正の往復が増えるか | 3 件とも 1 回目のレビューで ok、修正の往復は 0 回。ready からマージは 14〜17 分 | 件数が少なく比べられない（差は見えない） |

時刻はすべて UTC。ready・着手・マージの時刻は、D の取りまとめ役が 60 秒ごとに取った GitHub の状態の記録と Issue が閉じた時刻による。60 秒ごとの記録なので、1 分ほどずれることがある。レビューの回数は、PR が Ready のあと、レビューで draft に戻らずにマージまで進んだことによる。

## 分かったこと

- 実際に使うと、受入条件とレビューでは見つからない抜けが見つかった。特に「入口が無い」は、後ろの機能を Issue に分けて作るほど見えにくくなった。後ろの機能のどの Issue も、自分の受入条件の中では正しかったため。
- 見つけた困りごとは、受入条件にしやすかった。使い直しで確かめる手順も、見つけたときの操作をそのまま使えた。
- 使い直しの 1 回目は無効だった。D が探索のために 21:20 に起動したアプリが止まっておらず、新しいアプリが同じポートで起動できずに、古いアプリに当たった。止める命令で指定したプロセス名が違っていたため。使い直しの前に、起動したアプリが新しいビルドかを確かめる必要がある。

## 残したこと

- 使う人の立場で動かす回は 1 回だけ。何件マージするごとに入れるとよいかは、まだ分からない（台帳 E16）。
- 取りまとめる人（承認する人）の立場では、一通り使っていない。
