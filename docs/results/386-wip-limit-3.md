時刻はすべて UTC。ready・着手・Ready・マージの時刻は、D の取りまとめ役が 60 秒ごとに取った GitHub の状態の記録と Issue が閉じた時刻による。60 秒ごとの記録なので、実際の時刻と 1 分ほどずれることがある。「レビューの ok」は、`merge-check` が ok を返した時刻。レビューの回数は、PR が Ready のあと draft に戻らず、最初の ok でマージまで進んだことによる。

## 分かったこと

- 止まりも待ちも無ければ、難しい用の実装を含めて、ready から 15 分以内にマージまで進んだ。
- 人の役の時間（レビューの ok から `merge:requested` まで）は約 1 分だった（2 件とも、20:26 の ok から 20:27 に付けた）。`merge-check` の ok を知らせる監視があり、難しい用の PR は差分を読んでから付けたため。
- 同じファイルを変えない 2 件を、同時に着手させた。同じファイルの待ちも、マージの後の衝突も起きなかった。

## 残したこと

- 2 件だけで、作業中が 3 件だった時間も約 5 分なので、作業中 3 件までで使用量の上限に当たらずに長く流せるかは判定できない。続きは #394 で確かめる。
