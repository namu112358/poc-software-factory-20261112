# [SF-D][Epic] 連携スクリプトが API で書き込むときの抜けを直す（#511）の結果

連続運転 D（2026-11-13、計画は #122）のうち、社内の連携スクリプトが API でタスクを書き込む立場で使って見つけた困りごとを直した Epic の結果です。使う人の立場で動かす回の 9 回目です（台帳 E16）。3 回目（#426）の連携スクリプトの回は読み取りが中心だったので、今回は書き込みを見ました。

## 確かめたいこと

- API で書き込むときに見つけた困りごと（`docs/product.md`、PR #515）から作った Issue が、受入条件どおりに直るか。
- 書き込みの API で、読み取りの回では出なかった種類の困りごとがあるか。

## 見つけ方

2026-11-13 03:38 に、main（8fb4725）を `npm start` で起動し、Node の `fetch` だけで API を呼んだ（画面は使わない）。次の 8 つを試した。

- 応答の形
- 誤った入力
- 同時の更新
- 二重送信
- まとめての変更
- 削除のあとの操作
- 権限
- ログインの切れ

操作と記録はサブエージェント（sonnet）に任せ、困りごとの見立ては D がした。

本物の不具合として、次の 3 つを Issue にした。

- 期限に、存在しない日付（`2026-02-30` など）が保存された。延長の申請は同じ日付を断るので、API ごとに扱いが違った。
- ログインの API に JSON の Content-Type を付けずに送ると、500 で本文が空だった。
- 何も変えない更新（`PATCH {}`）でも更新日時が進み、同時の更新を確かめているほかの人の保存が 409 で断られた。

次の 3 つは、今の API の振る舞いを変えると、すでにある連携スクリプトを壊すおそれがある。そのため Issue にせず、人の判断に残した（Epic #511）。

- `expectedUpdatedAt` を付けない更新は、ほかの人の更新を黙って上書きする。
- 知らない項目（項目名のタイプミスを含む）は、黙って無視される。
- 同じ内容の作成を 2 回送ると、2 つできる。

次の 3 つは、困りごとにしなかった。

- ほかの人の担当のタスクも編集できる（チームで使う作り。削除と元に戻すは担当者だけ）。
- まとめての変更は、存在しない ID が 1 つでも混ざると全部を断り、その ID を応答に並べる。
- 延長の申請の承認の権限。

確かめ直しの中身:

1. #512（存在しない日付）
   - `2026-02-30`・`2026-04-31`・`2025-02-29` は、作成・更新とも 400 で、保存されなかった。
   - `2028-02-29` は受け付けた。
   - 画面の日付の入力欄では、存在しない日付は入らなかった。
   - 延長の申請も、今までどおり 400 だった。
2. #513（ログインの 500）
   - Content-Type が無いときと `text/plain` のときは、415 と `{ error, details }`（「JSON かフォームで送ってください」）が返った。
   - JSON・フォームのログインの成功と失敗は、今までどおりだった。
   - サーバーのログに例外は出なかった。
3. #514（何も変えない更新）
   - `PATCH {}` と今と同じ値だけの更新では、更新日時が進まなかった。
   - そのあと、ほかの人が読んだ時点の更新日時を付けて保存すると、通った（409 にならない）。
   - 値が変わる更新は、今までどおり更新日時が進み、古い更新日時の保存は 409 になった。

時刻はすべて UTC。ready・着手の時刻は GitHub のラベルのイベント、マージの時刻は PR のマージの時刻による。

## 分かったこと

- 同じ「日付」でも、API ごとに検証の関数が分かれていて、扱いがずれていた。画面の日付の入力欄は存在しない日付を入れさせないので、画面から使う限りは見えなかった。
- 3 件とも、レビューを通った後、`risk:high` が付かずに自動でマージのキューに入った（#461 の後）。
  - #513 はログインの route を変えたのに `risk:high` が付かず、台帳 E26 に足された。高リスクと判定するファイルの一覧に、ログインの API を足す。
  - D のマージ後の確かめでは、見逃された不具合は 0 件だった。
  - #461 の後に、`risk:high` なしで自動でマージされた PR を D が確かめた合計は、9 本で見逃し 0 件。
- 3 件とも、ready から着手まで 2 分以内、マージまで 15 分以内だった。

## 残したこと

- `expectedUpdatedAt` なしの上書き・知らない項目の無視・二重の作成は、人の判断（Epic #511）。
- 一覧の API（`GET /api/tasks`）にはページ送りが無く、`limit` を付けても全件を返す（対象外）。
