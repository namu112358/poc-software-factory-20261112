# 「罠」に足した決まりの効き目（Epic #121）

2026-11-12 に、振り返りの役が `AGENTS.md` の「このプロジェクトの罠」に足した決まりが、実装の役（Sonnet 5.5）の最初の実装を変えるかを確かめた結果です。判定は、どれもレビューの前の最初のコミットで行いました。

## 結論

- **効いたのは、コードからも一般の作法からも推し量れない、このプロジェクトだけの決め事。** 「新しい画面はヘッダーにリンクを足す」は、決まりの前は 2 件中 0 件、足した後は 2 件中 2 件で守られた。比べるために置いた、決まりの無い「戻るリンクを付ける」は、前も後も 0/2 で変わらなかった。
- **推し量れる落とし穴は、決まりが無くても避けられた（6 件中 6 件）。** 区切りの無いリンクの並び、UTF-16 の文字数、updated_at の更新漏れ、テストの期待値を実装と同じ式で作る、の 4 種類。決まりを足しても、効き目は測れない（要らない）。
- **指示ファイルには、コードから分からない決まりだけを書く。** `AGENTS.md` の API の一覧は 4 件のまま更新されず（実際は 30 件以上）、「一覧に新しい API が無い」という任意の指摘が 15 の PR でくり返された。一覧のように、コードを見れば分かる情報は古くなり、正しいものとして読まれる。説明は `docs/` に移し、一覧はやめた（#290）。

## 比べた結果

| 落とし穴 | 決まり | 結果 | Issue・PR |
|---|---|---|---|
| 1 つの欄に複数のリンクを区切らずに並べる | あり（#48） | 2/2 で避けた | #106・#114、#109・#124 |
| 文字数を UTF-16 の単位で数える（対照） | なし | 2/2 で避けた | 同上 |
| タスクを変える新しい API で updated_at を変えない | なし | 2/2 で避けた | #159・#166、#161・#167（試行なので閉じた） |
| テストの期待値を実装と同じ式で作る（対照） | なし | 2/2 で避けた | 同上 |
| 新しい画面へのリンクをヘッダーに足さない | 足す前（無し） | 0/2 で守った | #106、#109 |
| 同上 | 足した後（#178） | 2/2 で守った | #181・#205（閉じた）、#182・#222 |
| 「← タスク一覧へ戻る」を付けない（対照） | なし | 前 0/2、後 0/2 | 同上 |

根拠（記録で確かめたこと）:
- #222 の本文に「Issue の指定ではないが、新しい画面にはヘッダーのリンクを足す決まりのため」とある。
- #181 のセッションは、`src/app/layout.tsx` を読む前に、ヘッダーを変える見込みをコメントに書いた。

## 限界

- 件数は条件ごとに 2 件。決まりの前と後で、題材の画面（Issue）が違う。
- 実装の役のモデルは Sonnet 5.5 だけ。
- セッションの記録には思考の中身が残らないので、決まりを使ったかは、本文やコメントで言及したときしか確かめられない。#227 の後は、PR 本文の「当てはめた罠」の行で数えられる。
