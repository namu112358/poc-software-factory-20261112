# [SF-D][Epic] 同時の編集と操作の誤りで、入力や記録を失わないようにする（#444）の結果

連続運転 D（2026-11-12〜13、計画は #122）のうち、「良くしたいこと」の 4（同時に触っても、間違えて操作しても、データを失わない）を、佐藤・鈴木・田中の 3 人で同時に使って確かめ、見つけた困りごとを直した Epic の結果です。使う人の立場で動かす回の 5 回目です（1〜4 回目は #411・#421・#426・#435。台帳 E16）。

## 確かめたいこと

- 3 人で同時に使って見つけた困りごと（`docs/product.md`、PR #448）から作った Issue が、受入条件どおりに直るか。
- 前の Issue で「対象外」とした部分が、使う人には困りごととして残っていたか（台帳 E18）。

## 見つけ方

2026-11-12 23:52 に、main（#442 のマージ後）を `npm start` で起動した。Playwright で 3 人のブラウザを同時に開き、次を試した。

1. 佐藤と鈴木が、同じタスクを同時に編集する（佐藤はメモ、鈴木は期限）。
2. 佐藤が編集を開いている間に、田中がまとめてステータスを変える。
3. コメント・タグ・延長の申請があるタスクを、削除して戻す。
4. 期限切れのタスクをアーカイブする。
5. コメントを削除する。

困りごとが 2 つ見つかった。どちらも、前の Issue で対象外とした部分だった。

- コメントを削除すると、二度と戻らなかった（#374 で「削除したコメントを戻す機能」を対象外にしていた）。
- 同時に編集して後から保存した鈴木が断られ、「今の値で編集し直す」を押すと、鈴木が入れた期限（11/27）が消えた。相手（佐藤）が変えたのはメモだけだった（#385 で「項目ごとに選んで混ぜる機能」を対象外にしていた）。

次の 3 つは、困りごとにしなかった。

- 同時の編集は、後からの保存が断られ、相手が変えた項目が表に出た。まとめての変更と編集が重なったときも断られた。
- タスクを削除して戻すと、コメント・タグ・承認待ちの延長の申請が戻った。
- アーカイブしたタスクは、期限切れの一覧・ボード・メンバーの一覧から消えた。これは #259 で決めた「やめたタスク」の扱いどおり。

## 分かったこと

- 5 回目の困りごとは 2 件とも、前の Issue で対象外とした部分だった。1 つずつの Issue で範囲を絞るのは正しい判断だった。ただ、絞った分は記録に残らず、使う人の立場で動かすまで見つからなかった。
- 台帳 E18 の決まり（対象外にした部分を別の Issue として残す）を、この Epic で初めて当てはめた。#445 で対象外にした「コメントの編集の前の本文」を、#447（`status:ready` なし）として残した。
- 2 件とも、ready からマージまで 15 分以内だった。どちらも難しい用で、レビューは 1 回で ok だった。
- D がラベルの付け方を変えた。Issue を作るときは状態のラベルを付けず、2 件の ready を約 2 分あけて付けた。1 つの Issue に実装が 3 つ同時に着手したことがあったため（台帳 E19）。2 件とも、PR は 1 本ずつだった（同時の着手が重なったかは、セッションの数を数えていないので確かめていない）。

## 残したこと

- #447（コメントの編集の前の本文を見られるようにする）は、`status:ready` を付けずに残した。要るかどうかを決めてから着手する。
- 使う人の立場で動かす回を、何件マージするごとに、どの立場で入れるとよいかは、まだ決めていない（台帳 E16）。B が、別の立場（初めて使う人・キーボードと読み上げ）で回している（Epic #451）。
