# [SF-D][Epic] 画面と API の振る舞いのずれをなくす（#430）の結果

連続運転 D（2026-11-12、計画は #122）のうち、画面と API の振る舞いのずれが、ほかにも残っていないかを確かめて直した Epic の結果です。ずれは、#426（連携スクリプトの立場で API だけを使う回）で初めて見つけました。原因は、画面の機能を足すときに「API は対象外」とした Issue が重なったことです。

## 確かめたいこと

「API は対象外」とした Issue のうち、#426 で直したもの（#348・#392・#398 → #425）のほかにも、画面と API のずれが残っていないか。残っていれば、直して、画面・CSV・API の結果がそろうか。

## 見つけ方

Issue の本文に「対象外」と「API」を含む SF-D の Issue を検索した。その中から、対象外の欄で API を外した Issue を選び、1 件ずつ見た。見たのは、画面と CSV が使う一覧の取得の指定と、API が使う指定の違い。

| Issue | 画面だけにした内容 | ずれか |
|---|---|---|
| #348・#392・#398 | 複数の担当者・複数のタグ・期限での絞り込み | ずれ。#425 で直した（#426） |
| #368 | キーワードで、コメントの本文も探す | **ずれ**。画面と CSV は探すが、API は探さない → #429 |
| #375 | 担当者を選ぶときに、その人の未完了と期限切れの数を見せる | ずれではない。選ぶ画面の見せ方で、API の結果は変わらない |
| #379 | 絞り込みと並べ替えを、次に開いたときにも残す | ずれではない。ブラウザで覚えるだけで、API の結果は変わらない |

ほかに Epic の本文で挙げた #350・#367・#369・#384 は、画面の見せ方の変更だった（ログイン後に目に入るもの、自分の申請の結果、新しく担当になったタスクの知らせ、長く待っている申請を目立たせる）。API の一覧の結果を変えるものではないので、ずれではない。

この表は、Issue の本文と一覧の取得の指定を読んで判断した。#375・#379・#385 と、#350・#367・#369・#384 については、API を呼んで確かめてはいない。

## 分かったこと

- 対象外の欄で API を外した SF-D の Issue は 7 件（#348・#368・#375・#379・#385・#392・#398）。そのうち 4 件が、後で画面と API のずれとして直す必要があった。一覧の結果を変える機能（絞り込み・検索）を画面だけに足すと、ずれになる。見せ方だけの機能はずれにならない。
- 直し方は 2 回とも、画面と CSV が使う指定を API でもそのまま使うことだった。#429 の直しは 1 行だった。
- この学びは、台帳 #123 の E18 に仮説として足した。機能の Issue テンプレートの受入条件の説明に、「画面と API の両方に効くかも書く。片方を対象外にするなら、別の Issue（status:ready なし）として残し、番号で参照する」を足した（PR #431）。

## 残したこと

- E18 の仮説（対象外を別の Issue に残すと、後から見つかるずれが減るか）は、次からの Issue で測る。今の値は 7 件中 4 件。
