## 分かったこと

- レビューの「任意」の指摘を数えておくと、くり返したものの多くは、使う人に見える抜けとして残っていた。任意のまま流すと、別の機能を足すたびに同じ形の抜けが増える。
- 受入条件に書かない落とし穴のうち、境界値は実装の段で拾えた。同時更新は、実装とレビューが気づいても「範囲外」として残した。
  - 範囲外と書いたものを、その場で別の Issue に残す決まり（台帳 E18）が、PR の段では働かなかった。
  - 今回は、D がマージ後に確かめて Issue にした。
- この Epic の途中で、レビューを通った PR は、`risk:high` 以外は自動でマージのキューに入るようになった（#461）。
  - D が差分を読むのは `risk:high` の PR だけになった。
  - API の応答を変える PR（#492・#494）には、`risk:high` が付かなかった（台帳 E26）。
  - マージ後の確かめで、レビューで見逃された不具合は 0 件だった。

## 残したこと

- タグの入力欄では、絵文字のように 1 文字が 2 つ分に数えられる文字は、10 個までしか入らない（めったに無いので Issue にしていない）。
- ログインが切れたときの表示で、中身が空の警告の要素がもう 1 つ出る（読み上げで「警告」とだけ読まれることがある）。次に同じフォームを触る Issue で、ついでに 1 つにまとめる。
- #363（main を壊す不具合の直しと、同じファイルを待つ Issue の重なり）は、本物の不具合が無かったので測っていない。
