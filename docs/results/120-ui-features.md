## 分かったこと

- 止まりも割り込みも無いとき、中くらいの機能の追加は、ready から 16〜20 分でマージまで進んだ。
- 時間を大きく延ばしたのは、作業そのものではなく、待ちだった（#100 の 2 時間 30 分）。待ちの中身は、ファイル単位の衝突の予防によるキューの待ち（#183・#275）と、利用上限による停止（#219）。
- レビューの必須の指摘が出たのは、受入条件の言葉（「利用者の一覧」）と、既存の関数の意味（`listAssignees()` は「タスクを持つ人」）がずれていたところ。レビューの役は受入条件と照らして見つけた。
- 正当な制約（置き場所の指定）には、実装の役は従った（B の試行）。

## 残したこと

- CI の初回合格率は、この Epic では集めていない。D の全体の集計で扱う。
