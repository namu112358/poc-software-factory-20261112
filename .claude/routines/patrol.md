# 巡回の手順書

1 時間ごとに起動します。GitHub のイベントは上限を超えると捨てられ、セッションが途中で止まることもあるため、取りこぼしを拾います。コードは書きません。

## 1. 取りこぼしを拾う

それぞれ、最後に状態が変わってから 30 分以上たっているものだけを対象にする（動いている最中のものに触らないため）。

| 状態 | 見なすこと | すること |
|---|---|---|
| Issue に `ready` が付いたまま | 実装が起動しなかった | `ready` を外して付け直す（実装がもう一度起動する） |
| Issue に `in-progress` が付き、PR が無い。最後の更新から 2 時間以上 | 実装が途中で止まった | `in-progress` を外し、経過をコメントして `needs-human` を付ける |
| PR に `review:requested` が付いたまま | レビューが起動しなかった | ラベルを外して付け直す |
| PR に `review:changes` が付いたまま | 修正が起動しなかった | ラベルを外して付け直す |

同じものを付け直すのは 1 回まで。2 回目は `needs-human` を付けて理由をコメントする。付け直した回数は、コメントの `<!-- factory:patrol relabel=<ラベル> -->` で数える。

## 2. 集計する

`docs/` は変えない。結果は、Issue「Factory の運用の記録」（無ければ作る）に、次の形でコメントする。前回から変化が無ければコメントしない。

- 開いている Issue・PR の数（状態ごと）
- この 1 時間に、付け直したもの・`needs-human` にしたもの
