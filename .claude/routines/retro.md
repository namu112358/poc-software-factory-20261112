# 振り返りの手順書

1 日 1 回起動します（人が「今すぐ実行」してもよい）。マージされた PR のレビューの指摘から、ほかの機能でもくり返しそうな決まりを拾い、`AGENTS.md` の「このプロジェクトの罠」に足す案を、人が判断できる PR にします（開発標準 §2.10 の改善ループ）。コードは書きません。

## 1. 指摘を集める

前回の振り返り（Issue「Factory の運用の記録」にある `<!-- factory:retro until=<日時> -->` のコメント）より後にマージされた `claude/` の PR を集める。前回が無ければ、すべてのマージ済みの PR を対象にする。

それぞれの PR のレビュー（`<!-- factory:review verdict=changes ... -->`）の「必須」の指摘と、修正の役のコメント（`<!-- factory:fix -->`）を読み、指摘ごとに「何がまずかったか」を 1 行にまとめる。`main` との衝突だけの指摘は除く。

「任意」の指摘も、同じように 1 行にまとめる。任意の指摘は、前回までの振り返りの期間も含めて 3 つ以上の PR でくり返したものだけを、次の「2.」の候補にする（任意の指摘は 1 回では直されないので、くり返しの数で選ぶ）。

### 流れの止まり・遅れも集める

同じ期間について、次のものも集める（レビューの指摘には出ない、流れの問題を拾うため）。対象は、マージされた `claude/` の PR に加えて、同じ期間にマージされずに閉じた `claude/` の PR と、それらの Issue。マージされずに閉じた PR は、閉じたときのコメントに止まりの原因が書かれていることが多い（2026-11-12 の #58 では、「ブランチが古い版から作られていた」という原因が、そこにしか無かった）。

- `ready` から PR が Ready になるまでに 10 分以上かかった Issue と、その間に何が起きたか（衝突・CI の待ち・キューの待ち など）
- 実装・修正の役が、待ちきれずに終えたり、`needs-human`・`blocked:question` で止まったりした回と、その理由。理由は役のコメントだけでなく、その後に人や別の役が書いたコメントと、PR を閉じた理由まで読む
- 衝突で draft に戻された回数（PR ごと）と、キューで待った時間
- レビューで `verdict=ok` になってからマージされるまでに 10 分以上かかった PR と、その間に何が起きたか（Mergify のキューから外れた・衝突・人の判断の待ち など）

時刻は次の道具で取る（GitHub MCP の `issue_read` では、ラベルが付いた時刻が取れない）。

- ラベルが付いた・外れた時刻: REST の `GET /repos/{owner}/{repo}/issues/{number}/events`（`labeled`・`unlabeled`）
- PR が Ready になった・draft に戻った時刻: REST の `GET /repos/{owner}/{repo}/issues/{number}/timeline`（`ready_for_review`・`convert_to_draft`）
- Mergify のキューの出入り: PR の Mergify のコメント

## 2. くり返しそうなものを選ぶ

次の 2 つをどちらも満たすものだけを選ぶ。満たすか迷うものは選ばない。

- その機能だけの話ではなく、ほかの機能を作るときにも同じ間違いが起きうる（例: 「一覧で複数の値を区切らずに並べた」は、ほかの一覧でも起きうる。「延長申請の理由の上限を間違えた」は、その機能だけの話）。
- `AGENTS.md`（コーディング規約・罠）に、まだ同じ内容が無い。

流れの止まり・遅れは、原因が手順書（`.claude/routines/`）にあり、手順書を直せばくり返さないものだけを選ぶ（1 回の振り返りで 2 件まで）。原因が手順書の外（Routine の設定・`.mergify.yml`・Ruleset）にあるものは選ばず、「4.」の記録にだけ書く。

選ぶ前に、その原因がもう直っていないかを確かめる。出来事の時刻より後に `.claude/routines/` を変えたコミット（`git log --since=<出来事の時刻> -- .claude/routines/`）と、出来事に付いたコメント（「直した」「指示文を変えた」など）を読む。直っていれば選ばず、「4.」の記録に「直し済み（#番号）」と書く。

## 3. 案を PR にする

選んだものがあれば、`claude/retro-<日付>` のブランチで、`AGENTS.md` の「このプロジェクトの罠」に 1 件ずつ足し、draft の PR を出す。

- 書き方は `AGENTS.md` の「罠」の書き方に合わせる（言い切りの規約の行と、その下の「理由」の行）。理由には、きっかけになった PR の番号を書く。
- 1 回の振り返りで足すのは 3 件まで。多ければ、くり返しそうな順に選ぶ。
- PR は draft のままにする（Ready にしない。レビューの役ではなく、人が判断する）。

流れの止まり・遅れの直しは、別の draft の PR（`claude/retro-flow-<日付>`）で、`.claude/routines/` の手順書を直す案として出す。何が起きたか（Issue・PR の番号と時刻）と、直した後にどう変わるかを本文に書く。

選んだものが無ければ、PR は出さない。

## 4. 記録する

Issue「Factory の運用の記録」に、`<!-- factory:retro until=<今回の対象の最後のマージの日時> -->` を先頭に付けて、集めた指摘の数・選んだもの（と PR の番号）・選ばなかった主なものとその理由を、短く書く。
